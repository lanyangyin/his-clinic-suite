# 医院对照审计（门诊 + 治疗室）

审计口径：

- 对照对象：国内二级/三级医院门诊的常见做法，同时区分“三级医院必须、基层门诊可简化”。
- 只看当前代码和页面实际有的字段/接口，不按宣传口径。
- 住院、手术室不在当前业务范围，不作为必改项。
- 结论用于排优先级，不是“功能越多越像医院”。

## 总评

当前系统已经是一条能跑通的门诊交易闭环：

```
建档 → 挂号 → 分诊 → 接诊/病历 → 开方/检验/治疗
→ 收费/发票/退费 → 药房发药/退药 → 库房出入库
→ 检验报告/审核 → 治疗室处置/随访 → 病案归档
```

和医院真正的差距，主要不在“页面多少”，而在四条线：

1. **临床安全**：过敏、生命体征、诊断编码、危急值闭环、输液核对
2. **医保合规**：患者参保类型没有进入结算，真实接口未接
3. **药事/院感**：GSP 召回与库存发药脱节，治疗室器械灭菌未联动
4. **法律证据**：知情同意只是布尔值，病案销毁只有审批人字符串

## 最值得先补的 8 项

### 1. 过敏史硬拦截（P0）

现状：过敏史已经建档，但 `app/modules/encounter/service.py` 的开方规则只有“同药重复”和“特殊抗菌药”，没有读患者过敏史。

医院做法：开方时按过敏原/药物类别交叉核对，命中必须停开或填理由强制 override，药房发药再核一次。

建议：

- 过敏原维护成结构化（青霉素类、头孢类、磺胺类、碘、酒精等）
- 开方命中 → 阻断；医生填“无交叉过敏依据”才能继续
- 发药时再次提示
- 记录 override 人/时间/理由

这是投入最小、收益最大的一项。

### 2. 门诊生命体征 + 分诊级别（P0）

现状：生命体征只在住院模块有；门诊分诊只有排队状态。

医院做法：分诊护士测体温、脉搏、呼吸、血压、SpO2，给 1–4 级分诊，异常直接提示医生。

建议：分诊台加一组生命体征和分诊级别；医生工作台显示；异常值红色。

### 3. 诊断编码（P0/P1）

现状：诊断是自由文本。

医院做法：ICD-10 编码 + 名称，统计、医保、病案首页都依赖它。

建议：先做“常用诊断字典 + 编码可选”，不要求医生一次录全；为医保/报表留接口。

### 4. 危急值闭环（P0/P1）

现状：检验报告可标危急值，记录通知对象；审核要求填通知对象。

医院做法：电话回读、医生确认、记录时间、超时升级、科室签收。

建议：增加“医生确认”按钮/时间；超时未确认在医生/护士工作台红色提醒。

### 5. 输液/治疗身份核对（P0/P1）

现状：配药核对人是一个自由文本，执行前没有腕带/扫码。

医院做法：腕带 + 扫码 + 双人核对 + 高危药双签。

建议：小诊所至少做“患者姓名+就诊号+药品”扫码/勾选核对，高危药要求第二人账号确认。

### 6. 医保患者类型进入结算（P0）

现状：`settle_payment` 只接收费用明细，不接收患者参保类型；患者 `insurance_type` 目前只存档。

医院做法：按参保类型、起付线、封顶线、目录限定支付结算。

建议：先把 `insurance_type` 传入结算适配器；真实医保接口后接。

### 7. GSP 召回联动库存/发药（P1）

现状：召回单是独立记录，库存和药房发药不受影响。

医院/GSP：召回批次要锁定库存、停止发药、追溯已发患者。

建议：召回按药品+批号锁定库存；发药时校验；生成已发患者清单。

### 8. 知情同意与病案销毁证据（P1）

现状：治疗室同意是布尔值；病案销毁只填审批人字符串。

医院做法：同意书版本、签名/指纹/电子签、时间；销毁要审批流和清册。

建议：先存“同意书版本 + 签署人 + 时间 + 签名图片”，销毁增加管理端审批状态。

## 不建议照搬医院的部分

- 住院、手术室、麻醉、ICU：当前明确不做。
- DRG/DIP、病案首页、三级质控：没有住院和医保接口前，投入产出低。
- 全院级高可用、双活、接口引擎：小诊所单机/局域网阶段不需要。
- 30 字段建档、复杂挂号类型：前台会变慢，P0 已够用。

## 建议的下一轮

按“患者安全优先”，建议先做两项：

1. **过敏史硬拦截 + override 留痕**
2. **门诊分诊生命体征 + 分诊级别**

然后再做：

3. 诊断编码
4. 危急值医生确认
5. 医保类型进入结算

这五项做完，系统会从“流程跑通”变成“临床敢用”。
