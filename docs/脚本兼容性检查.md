# Windows/Linux 启动脚本兼容性检查

## 现象

`dev_client.bat` 双击后出现：

```text
'exist' 不是内部或外部命令
'鍏堟墽琛岋細py' 不是内部或外部命令
'b' 不是内部或外部命令
```

不是 Python 报错，是 `cmd.exe` 解析批处理文件失败。

## 根因

原文件同时存在三个问题：

1. **只有 LF 换行，没有 CRLF**
   - Windows `cmd.exe` 按行解析 `.bat` 时，`if not exist` 和下一行被拆坏
   - 于是出现 `'exist'` 不是命令
2. **UTF-8 中文 + chcp 65001**
   - cmd 在切换代码页前后解析中文，容易出现乱码和括号截断
   - 中文全角括号会进一步破坏 `if (...)` 块
3. **文件无 BOM**
   - 不是主因，但和 LF、中文叠加后更容易出问题

## 修复

所有 Windows 批处理统一为：

- ASCII only
- CRLF
- 无 BOM
- 不使用 `chcp`
- 使用 `goto` 标签代替复杂中文括号块
- 统一 `cd /d "%~dp0"`
- 所有路径加引号

已处理：

```text
dev_client.bat
dev_server.bat
start.bat
backup.bat
scripts/build_client.bat
scripts/build_server.bat
scripts/install_autostart.bat
scripts/install_service.bat
scripts/uninstall_autostart.bat
scripts/uninstall_service.bat
```

提示信息改为英文，避免任何代码页问题；程序界面仍是中文。

## Linux/macOS 脚本

统一 LF：

```text
backup.sh
start.sh
scripts/build_server.sh
scripts/install_service.sh
scripts/uninstall_service.sh
scripts/run_server_linux.sh
```

其中 `run_server_linux.sh` 原来被写成了 CRLF，Linux 下会报 `bad interpreter`，已修正。

## 防止复发

新增 `.gitattributes`：

```gitattributes
*.bat text eol=crlf
*.cmd text eol=crlf
*.sh  text eol=lf
*.ps1 text eol=crlf
*.service text eol=lf
```

新增检查脚本：

```bash
python scripts/check_scripts.py
```

检查内容：

- `.bat/.cmd` 必须 CRLF
- 不能有 BOM
- 不能有非 ASCII
- 不能有 `chcp`
- 首行必须是 `@echo off`
- `.sh` 必须 LF、必须有 shebang

当前结果：

```text
checked 16 scripts
all scripts OK
```

## 验证

- `cmd.exe` 解析测试：`dev_client.bat` / `dev_server.bat` 不再出现 `'exist'` 报错
- Linux `bash -n`：6 个 shell 脚本全部通过

```bash
bash -n backup.sh
bash -n start.sh
bash -n scripts/build_server.sh
bash -n scripts/install_service.sh
bash -n scripts/uninstall_service.sh
bash -n scripts/run_server_linux.sh
```

## 如果旧目录还是报错

优先重新拉取仓库，不要只手改换行：

```bash
git pull
python scripts/check_scripts.py
```

如果 Windows 检出仍是 LF：

```bash
git config core.autocrlf true
git checkout -- dev_client.bat dev_server.bat start.bat backup.bat
```

或在编辑器右下角把换行从 `LF` 改成 `CRLF`。

## 注意

- `.bat` 只适用于 Windows；Linux 用 `.sh`
- `dev_client.bat` 需要项目根目录已有 `.venv`
- 新建 `.venv`：

```bat
py -3.12 -m venv .venv
```

- 服务端和客户端不要共用一个 Linux `.venv` 和 Windows `.venv`
