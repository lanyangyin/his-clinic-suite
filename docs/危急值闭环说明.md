# 危急值闭环说明

## 数据

`lab_requests` 新增：

- `critical_ack_by`：确认医生
- `critical_ack_at`：确认时间
- `critical_ack_note`：确认备注

接口返回同时计算：

- `critical_pending`：是否未确认
- `critical_age_minutes`：报告后经过分钟数
- `critical_overdue`：未确认且 ≥ 30 分钟

## 流程

```
检验科报告（critical_flag=true）
  → 登记通知对象/时间
  → 医生工作台“危急值待确认”出现
  → 医生电话回读/处理
  → 填写备注并确认
  → 列表消失，记录确认人/时间
```

## 接口

医生工作台：

```http
GET /lab/critical-alerts
```

确认：

```http
POST /lab/requests/{id}/critical-ack
{"note": "已电话回读，患者已处理"}
```

规则：

- 只有医生角色可确认
- 必须是危急值
- 必须先登记通知对象
- 不能重复确认
- 已确认后不再出现在待确认列表

## 医生工作台

门诊工作台新增“危急值待确认”区域：

- 患者、项目、结果、报告时间
- 超时分钟数，≥30 分钟标“（超时）”
- 整行红色
- 选中后填备注，点“确认危急值”

界面证据：`docs/screenshots/critical_alert.png`

## 边界

- 30 分钟是当前固定阈值，未做成可配置。
- 超时只做红色提醒，没有短信/电话/护士站自动升级。
- 确认是医生手工操作，没有强制回读校验。
- 危急值通知对象仍是自由文本，未绑定具体医生账号。
