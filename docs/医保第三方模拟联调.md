# 医保第三方模拟器联调（1.3.9）

## 一、适用边界

本系统当前国家医保适配器是 **plain 明文模板**：

- 发送 `POST application/json`；
- `input` 是明文 JSON 对象；
- 不发送真实 `sign`/SM4 密文；
- 响应不验签、不解密。

因此适合接：

- 允许明文 input 的第三方模拟器；
- 自己写的测试桩；
- 本地联调/演示。

不适合直接接：

- 强制 SM2 签名、SM4 加密的真实前置机；
- 只接受 WinServiceAPI 动态库的医保客户端；
- 需要医保签到/签退流的正式环境。

## 二、本地模拟器

仓库自带：

```text
scripts/insurance_simulator.py
```

启动：

```powershell
.\.venv\Scripts\python.exe scripts\insurance_simulator.py --port 9099
```

端点：

```text
POST http://127.0.0.1:9099/success
POST http://127.0.0.1:9099/business-error
POST http://127.0.0.1:9099/malformed
POST http://127.0.0.1:9099/timeout
```

- `success`：2203/2204/2206/2207/2208 正常返回；
- `business-error`：返回 `infcode=1`；
- `malformed`：返回非 JSON；
- `timeout`：20 秒不响应，用于验证超时边界。

模拟器会校验外层必填：

```text
infno / msgid / mdtrtarea_admvs / insuplc_admdvs /
recer_sys_code / infver / opter_no / fixmedins_code / input
```

缺少任一字段返回业务错误，不会伪造成功。

测试值：

```text
机构编码：H999999
机构名称：模拟医院

安全模式：plain
签名类型：SM2
接口版本：V1.0
接收系统编码：HIS
医疗类别：11
操作员编号：SIM01
超时：5
重试：0

```

然后调用：

```text
GET  /insurance/national/status
POST /insurance/national/pre-settle/{encounter_id}
POST /insurance/national/settle/{encounter_id}
POST /insurance/national/cancel-settle/{encounter_id}
GET  /insurance/national/transactions
```

## 四、客户端

客户端 `ApiClient` 已增加：

```python
national_insurance_status()
national_pre_settle(encounter_id)
national_settle(encounter_id, setl_id)
national_cancel_settle(encounter_id, setl_id)
national_insurance_transactions(encounter_id)
```

收费员/管理员账号可用。

## 五、生产参数清单

机构上线前在网页填写：

### 机构/网络

- 机构编码 `fixmedins_code`
- 机构名称
- 前置机 URL
- 访问令牌
- 区域编码
- 就医地编码 `mdtrtarea_admvs`
- 参保地编码 `insuplc_admdvs`

### 报文

- 接口版本 `infver`
- 接收系统编码 `recer_sys_code`
- 医疗类别 `med_type`
- 操作员编号
- 签名类型
- 设备编号 `dev_no`
- 设备安全信息 `dev_safe_info`

### 安全/连接

- 安全模式 `plain` / `sm2_sm4`
- 证书路径
- 证书口令
- SM2 私钥/公钥
- SM4 密钥
- 超时秒
- 重试次数

### 当前明确未实现

`sm2_sm4` 的加密/签名流程尚未实现；选择它时服务端会明确拒绝调用，不会伪造成功。正式上线需要按当地规范补：

- SM4 加密/解密；
- SM2 签名/验签；
- 证书加载；
- 签到/签退；
- 地方返回码；
- 真实待遇计算。
