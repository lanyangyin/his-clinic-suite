# 临床核心重构落地说明

## 已完成

### 1. 处方头、类型与 5 种限制

新增：

```text
app/modules/encounter/models.py
  Prescription
  PrescriptionItem.prescription_id
```

字段：

```text
prescription_no
type：western / tcm_herb / narcotic / special
status：pending_review / approved / rejected / dispensing / dispensed / cancelled
prescribed_by
reviewed_by / reviewed_at / review_note
insurance_upload_status / insurance_uploaded_at
```

兼容：

- 保留 `PrescriptionItem.encounter_id`，旧查询不改；
- 旧数据回填为 `status=approved` 的 `RXLEGACY...` 处方头；
- 现有单条/批量开方 API 继续可用，返回增加处方头字段；
- 5 种限制按 `prescription_id` 计数。

### 2. 麻精药品专用处方与处方权

新增：

```text
drugs.controlled_level："" / narcotic / psychotropic1
users.narcotic_right
```

规则：

- 管制药品自动进入 `type=narcotic` 处方头；
- 医生没有 `narcotic_right` 时拒绝开方；
- 管理员默认放行；
- 由管理员授予：

```http
PUT /users/{user_id}/narcotic-right
{"enabled": true}
```

- 麻精处方不与其他西药混方，独立审方/发药；
- `narcotic_ledger` 记录发药/退药/空安瓿回收；
- `POST /narcotic/ampoule-return` 空安瓿回收，要求见证人；
- 盘点差异：`POST /narcotic/inventory-checks`，审批后按实盘数调整库存。

### 3. 药师审方

```http
GET  /pharmacy/prescription-reviews
POST /encounters/{encounter_id}/prescriptions/{prescription_id}/review
```

```text
pending_review → approved
pending_review → rejected（必须填原因）
```

配置：

```ini
[features]
prescription_review = true
```

测试环境通过 `HIS_REQUIRE_PRESCRIPTION_REVIEW=0` 保留旧用例。

驳回：

- 未收费处方明细和费用同步删除；
- 已收费处方禁止直接驳回，必须走退费；
- 发药前存在 `pending_review / dispensing` 处方则拒绝发药。

### 4. 医保按处方头逐张上传

```http
POST /encounters/{encounter_id}/prescriptions/{prescription_id}/insurance-upload
```

状态：

```text
not_ready → uploaded（真实 HTTP 成功）
not_ready → local（未配置医保地址，只记本地模拟）
```

限制：

- 只有 `approved` 处方可以上传；
- 上传记录写入 `approval_events`；
- 已新增 `insurance/prescription_upload.py` 适配器：未配置 URL 时记本地状态，配置后按一张处方一次 HTTP 调用；
- 真实医保平台仍需提供地址、Token、签名和回执格式。

### 5. 实际发药明细

```text
dispense_items
- dispense_id / prescription_item_id / drug_id
- drug_name / spec
- batch_no / expiry
- quantity / returned_quantity
- unit_price / amount
```

发药按近效期先出产生的批次逐行落明细；取药凭证优先显示实际批次、效期、数量。

退药按实际发药批次回补，记录 `returned_quantity`。

### 8. 统一审批

只读待办：

```http
GET /approvals/inbox
GET /approvals/summary
```

聚合：

- 待审处方
- 新药品/治疗项目建议
- 库房出库申请
- 采购申请
- 病案销毁申请
- 薪资申请

可配置步骤骨架：

```text
approval_requests
approval_steps
- biz_type / biz_id
- step_no / role_required / status
- approver / note / acted_at
```

处方审方已接入审批请求，支持按业务类型配置多级步骤：

```http
GET /approvals/flows/{biz_type}
PUT /approvals/flows/{biz_type}
GET /approvals/requests/{biz_type}/{biz_id}
POST /approvals/requests/action
```

动作：

```text
approve / reject / transfer / withdraw
```

已接入审批引擎：

- 处方审方（可多级）
- 采购申请
- 病案销毁
- 薪资申请
- 目录建议（药品：药师→库房；治疗：院长）

- `transfer` 可转交角色/指定人；
- `withdraw` 申请人撤回，处方同步作废并清理未收费明细；
- `overdue` / `escalate-due` 超时查询和升级院长；
- 处方第一步必须是药师；
- 客户端管理员新增“审批流程配置”；
- 审批提交/步骤/结果/超时升级写入 `notification_outbox`；
- `GET /notifications`、`POST /notifications/dispatch`，支持站内/企业微信/短信适配器。

默认单步，配置后例如：

```text
1 药师 → 2 院长
```

药师通过后处方仍为 `pending_review`，院长最终通过才变 `approved`。

事件时间线：

```text
approval_events
- biz_type / biz_id
- step / action / actor / note
```

```http
GET /approvals/history/{biz_type}/{biz_id}
```

### 9. 通用处方明细

新增：

```text
prescription_lines
- prescription_id / kind(drug/herb)
- drug_id / herb_id
- name / spec / quantity / unit
- dosage / frequency / route / days
- unit_price / amount
```

- 西药明细写入 `prescription_lines(kind=drug)`；
- 中药饮片明细写入 `prescription_lines(kind=herb)`；
- 旧西药/中药明细已回填；
- 统一查询：`GET /encounters/{id}/prescription-lines`。

中药待审处方也支持改剂量/特殊煎法/删除饮片，并同步金额、费用和通用明细。

处方明细数量修改会同步 `prescription_items`、`prescription_lines` 和未收费 `encounter_charges`；已收费必须先退费。

### 10. 统一处方中心

```http
GET /encounters/{encounter_id}/prescription-center
```

聚合：

- 西药/中成药处方头
- 中药饮片处方
- 治疗/处置单

中药饮片处方也创建 `prescriptions(type=tcm_herb)` 并挂 `prescription_id`。

客户端医生站新增“处方中心”页签；双击行跳转，选中处方可打开“编辑选中处方”修改待审明细的用法/频次/途径/天数或删除。

### 11. 按单张处方打印

```http
GET /print/prescription-header/{prescription_id}
```

客户端处方中心选中处方即可打印，不再只能打印整个就诊处方。

### 12. 审方后派生护理执行单

审方通过后调用护理 `sync_orders`，从已批准处方中 route=静滴/肌注的明细派生执行单；未批准处方不生成。
