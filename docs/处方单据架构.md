## 四套规则与现状

| 外部规则 | 要求 | 当前实现 | 差距 |
|---|---|---|---|
| 《处方管理办法》 | 中药饮片单独开方；西药/中成药可同方；每方不超过 5 种药品 | 有 `Prescription` 处方头/类型/处方号/状态；5 种上限按处方头；中药饮片仍独立 | 需继续补完整处方类型/麻精/处方权 |
| 医保电子处方 | 每次接口调用只上传一张处方 | 已有处方头，但医保上传仍是 Mock，没有 upload 状态 | 需补处方级上传状态与真实接口 |
| 执行链路 | 药品到药房；治疗到治疗室/护士；检查检验到医技；注射/输液派生执行单 | 药房发药、治疗单、检验/检查单已分开；护理执行有 `NursingOrder` | 注射/输液执行单没有从药品处方明细自动派生 |
| 麻精药品 | 麻精药品专用处方 + 处方权授权 + 调剂资格 | 无麻精字段/处方权/专用处方 | 完全缺失 |
| 特殊处方 | 皮试、输液、慢特病、出院带药等可配置 | 已有 `special` 类型占位，未做策略配置 | 需补场景规则 |

## 为什么不能把所有药塞进一张大表

不是界面问题，而是四个独立约束：

1. 处方法规按“处方”计数
2. 医保接口按“一张处方”上传
3. 执行部门按“单据终点”接单
4. 麻精药品按“处方权”独立流转

四个约束不能用一个“超级处方”同时满足。

## 目标模型

### 处方头

```text
prescriptions
- id
- encounter_id
- prescription_no
- type
- status
- prescribed_by
- created_at
- insurance_upload_status
- insurance_uploaded_at
```

### 处方类型

```text
western         普通西药/中成药
tcm_herb        中药饮片
narcotic        麻醉/第一类精神药品
special         皮试/输液/慢特病等可配置类型
```

说明：

- `western` 允许西药和中成药同方
- `tcm_herb` 强制独立
- `narcotic` 强制独立，并校验医师处方权
- `special` 按场景配置

### 处方明细

```text
prescription_items
- prescription_id
- drug_id
- quantity
- dosage/frequency/route/days
```

当前 `prescription_items` 直接挂 `encounter_id`，需要迁移为挂 `prescription_id`。

### 执行派生单

注射/输液：

```text
药品处方（prescription）
  └─ 处方明细：route=静滴/肌注
       └─ 执行单（nursing_order）
```

执行单不是处方，不替代处方；它只告诉护士：

```text
哪支药、什么剂量、什么途径、什么时候执行
```

治疗/处置：

```text
treatment_orders
```

检验/检查：

```text
lab_requests / imaging_requests
```

## 界面应该怎样

不要做一张“西药+中药+治疗”的混合处方。

应该是一个**处方中心**，内部按独立单据分区域：

```text
本次诊疗
├─ 西药/中成药处方（最多 5 种）
├─ 中药饮片处方（独立处方号）
├─ 麻精药品专用处方（独立处方号 + 处方权）
├─ 治疗/处置单
├─ 检验申请单
└─ 检查申请单
```

每个区域有独立头记录、独立状态、独立提交动作；底部可以有一个就诊级汇总，但汇总不是一张处方。
