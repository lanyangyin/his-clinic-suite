# 申请 / 审核 / 审批清单

## 1. 先区分三类“审核”

| 类型 | 例子 | 当前实现 |
|---|---|---|
| 业务审核 | 药师审方、检验报告审核、中药处方审核、CSSD 放行 | 分散在药房、检验、中药、CSSD |
| 行政审批 | 采购申请、病案销毁、薪资申请、新增药品/治疗项目 | 分散在院长、药事、库房、人事 |
| 回顾性质控 | 处方点评、病历质控 | `review` 模块 / 病历质控评分 |

这三类不能共用一个“通过/驳回”按钮就完事：

- 业务审核需要专业权限；
- 行政审批需要岗位/金额/层级；
- 质控是抽样评价，不是放行。

## 3. 标准里对应的“审核”要求

### 3.1 《全国医院信息化建设标准与规范》

不是单独一章“审批流”，而是分散在业务条款中：

- （24）门诊合理用药：医嘱自动审查、实时提醒、处方审核；
- （29）非药品医嘱执行：医嘱审核、执行确认；
- （30）药品医嘱执行：配药、核对、患者身份查对；
- （46）电子病历质量管理：环节/终末质控、整改；
- （49）危急值管理：报告、通知、接收、处理、升级；
- （51）药事信息管理；
- （52）处方点评；
- （53）发药管理；
- （58）院感管理；
- （61）医疗安全（不良）事件。

### 3.2 电子病历分级标准

需要分清级别：

- 3 级：处方/检验/检查/病历等数据跨部门共享；
- 4 级：全院共享，处方可关联药物知识、剂型/可供应提示；
- **5 级**：处方书写项目才明确要求针对诊断、性别、历史处方、过敏史做综合自动检查、处方权控制、传染病上报；
- **6 级**：跟踪处方执行、处方点评、药物不良反应记录与上报。

所以：

```text
“药师审方”是 NHC 合理用药/药事管理要求，
也是电子病历 5–6 级的能力；
不能简单说“没有审方就不符合电子病历 3 级”。
```

但当前系统如果要做“临床敢用”的门诊，处方审核仍然应优先补。

### 3.3 智慧服务标准

- 9 药品调剂与配送：处方确认、核对、合理用药检查；
- 16 安全管理：身份认证、权限；
- 17 服务监督：投诉/监督记录。

它不是临床审方标准，不能拿智慧服务评分替代药事审核。

## 4. 当前缺什么

### 4.1 已有统一待办、请求/步骤和流程配置

现在每个模块各自维护：

```text
status
reviewed_by
review_note
reviewed_at
```

问题：

- 院长/药师/库房没有“我的待办”统一列表；
- 无法按金额、类型、科室配置审批层级；
- 无法转交、撤回、催办、超时升级；
- 审计只能逐业务表查。

### 4.2 处方审方缺失

- 西药/中成药没有独立审方状态；
- `PrescriptionItem` 没有处方头，无法按处方审方；
- 药房可以直接发药，没有“审方通过”前置条件；
- 中药处方有审核，但西药没有，标准不一致。

### 4.3 审批证据不统一

- 有的表有 `reviewed_by/review_note/reviewed_at`；
- 有的只有 `approved_by` 字符串；
- 有的没有驳回原因；
- 已有 `approval_events` 时间线，但审批附件尚未统一。

### 4.4 薪资审批客户端入口不完整

后端有薪资申请/批准/驳回接口，但 HR 客户端目前主要是员工/医生/科室/账号，没有完整薪资审批页。

## 5. 建议的统一模型

不要把所有业务表改成一张大表；保留业务表，增加审批实例/步骤：

```text
approval_requests
- id
- biz_type        drug_proposal / treatment_proposal / purchase /
                  archive_destroy / salary / prescription_review
- biz_id
- title
- applicant
- status          pending / approved / rejected / cancelled
- current_step
- created_at

approval_steps
- id
- request_id
- step_no
- role_required
- approver
- action          approve / reject / return
- note
- acted_at
```

业务表保留自己的状态；审批中心只负责：

- 待办列表
- 通过/驳回/退回
- 审批意见
- 时间线
- 权限与审计

这样既不破坏现有流程，又能让院长/药师/库房有一个统一入口。

## 6. 优先级

### P0

1. 处方头 + 药师审方（西药/中成药）
2. 审方状态前置：未审方不能发药
3. 审批意见/驳回原因/审方人/时间统一留痕

### P1

1. 统一审批待办中心
2. 采购/销毁/薪资/目录建议接入统一时间线
3. 审批超时提醒、转交、撤回

### P2

1. 按金额/科室/类型的多级审批配置
2. 审批附件、电子签名、CA 验证
3. 审批效率统计

## 7. 结论

有申请审核，但分散：

```text
药事审核：有
库房/采购审核：有
病案销毁：有
治疗项目：有
中药处方：有
检验报告：有
西药处方审方：没有
统一审批中心：没有
```

下一步最值得做的是：

```text
处方头 → 药师审方 → 发药前置
再做一个统一待办/审批时间线
```

而不是先做一张“万能审批表”把现有业务状态全部推倒。
