# 主题实时跟随系统

## 原因

旧实现只在控件创建时调用一次：

```python
apply_theme(widget)
```

它会把浅色/深色 QSS 和调色板写到控件上，但没有监听系统主题变化。

所以在 Windows 设置里切换：

```text
浅色 → 深色
深色 → 浅色
```

已经打开的客户端不会刷新。

## 现在的实现

`his_client/ui/theme.py` 新增：

```python
install_theme_watcher(app)
```

入口 `his_client/__main__.py` 在创建 QApplication 后安装。

### 三重监听

1. `QStyleHints.colorSchemeChanged`
2. `QEvent.ThemeChange` / `QEvent.ApplicationPaletteChange`
3. 每 1.5 秒低频轮询系统亮度

第 3 层是为了兼容部分 Windows/Qt 组合下系统主题信号不触发的情况。轮询只比较亮度，不重建界面，开销很低。

### 主题变化时重新应用

- 全局 QSS
- QApplication 调色板
- 所有顶层窗口
- 自定义内联颜色控件：
  - `PatientBanner`
  - `PatientInfoPanel`
  - `SidebarTabs`
  - `DoctorWidget` 危急值标记
  - `BirthAgeEditor`
  - `LoginDialog` 提示/错误

### 不是所有颜色都跟随

有些颜色是业务语义色，故意不跟随主题：

```text
过敏/危急值：红色
警告：琥珀色
成功：绿色
```

这些颜色在浅色和深色下都必须保持警示含义，不能因为系统主题变化变成灰色。

## 强制主题

```powershell
$env:HIS_THEME = "light"   # 固定浅色
$env:HIS_THEME = "dark"    # 固定深色
```

设置后仍会安装监听，但 `is_dark()` 始终返回强制值，视觉上不会跟随系统。

## 验证

```text
启动客户端
Windows 设置 → 个性化 → 颜色 → 切换浅色/深色
客户端不重启，背景、输入框、表格、页签、患者卡、危急值标记应同步变化
```

## 边界

- 系统主题切换后，正在编辑的表单内容不丢失
- 不重建窗口，不打断当前患者
- 旧的自定义内联颜色如未注册监听，仍会保留旧值；本次已覆盖主要容器
- 语义色（红/黄/绿）不参与主题反转
