# 全系统表格只读审计

日期：2026-11-25
版本：1.3.9

## 根因

原实现依赖 `install_readonly_table_policy(app)` 在表格 `Show` 事件里关闭编辑触发器。正式客户端会安装策略，但独立科室演示脚本直接构造工作站控件，绕过了策略；且 `QTableWidgetItem` 默认带 `ItemIsEditable`，双击即进入编辑态。

## 修复

1. 新增 `ReadOnlyTable(QTableWidget)` 硬约束子类：
   - 构造即 `NoEditTriggers`；
   - 重写 `setEditTriggers`，未显式白名单时始终拒绝；
   - 重写 `edit`，仅 `allow_cell_edit=True` 且列在 `editable_columns` 时放行。
2. `his_client.ui` 包加载时把 `QtWidgets.QTableWidget` 替换为 `ReadOnlyTable`，因此：
   - 正式客户端；
   - 独立演示脚本；
   - 后续新增页面；
   只要从 `his_client.ui` 包导入，都自动使用只读表格。
3. 中药饮片表保留唯一例外：仅“剂量g”列（第 3 列）可编辑，且明确设置 `editable_columns=(2,)`。
4. 增加自动化测试：
   - 默认表格 `NoEditTriggers`；
   - 真实 QTest 双击不进入编辑态；
   - 白名单仅允许指定列；
   - UI 包内不得绕过只读策略；
   - 中药饮片剂量白名单存在。

## 全角色审计

脚本 `scripts/audit_tables.py` 遍历 14 个角色/工作站的所有页签，递归检查每个表格实例：

```text
admin 99；cashier 6；doctor 31；pharmacist 23；
warehouse 16；nurse 3；lab 2；radiology 1；
archive 3；director 9；hr_gui 6；treatment 4；
surgery 1；decoction 1
TOTAL 205  ALLOWED 2  ERRORS 0
```

- 205 个表格实例均为 `ReadOnlyTable`；
- 203 个默认只读，编辑触发器为 `NoEditTriggers`；
- 2 个白名单实例为中药饮片“剂量”列（admin/doctor 两个入口）；
- `edit()` 对非白名单列返回 False；
- 完整结果：`docs/table_audit.json`。

## 边界

- 管理台是 Web HTML 表格，不存在 QTableWidget 双击编辑问题；
- tcm 剂量列是业务要求允许编辑，但 ID/饮片/煎法列已禁止编辑；
- 任何后续新增 UI 文件只要位于 `his_client/ui` 下，会自动继承全局只读约束；若确需编辑，必须显式声明白名单列。
