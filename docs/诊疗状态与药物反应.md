# 诊疗状态与药物反应

## 接诊互斥

- 医生创建就诊时，若 `doctors.current_encounter_id` 指向 `open` 就诊，拒绝开始下一位
- 提示：当前患者尚未完成诊治，请先完成或挂起
- 接口：`POST /encounters/start`（桌面端使用）
- 旧接口 `POST /encounters/` 保留兼容，不强制互斥

## 挂起 / 继续

- `POST /encounters/{id}/pause`：状态改为 `paused`，允许先接诊其他患者
- `POST /encounters/{id}/resume`：恢复；若同一医生另有 `open` 就诊，拒绝
- 收费关闭就诊时，自动清空医生当前就诊指针

## 药物反应

`POST /encounters/{id}/adverse-reactions`

记录：

- 可疑药品
- 反应表现
- 严重程度（轻/中/重）
- 已采取措施
- 记录人

副作用：

- 就诊自动改为 `paused`
- 未完成护理执行单改为 `stopped`
- 医生工作站显示“药物反应 / 换药”对话框

## 换药流程（当前是受控人工流程）

1. 医生记录药物反应，就诊挂起
2. 护士停止输液/治疗
3. 药房按退药流程回补未用药品
4. 收费按退费规则处理
5. 医生恢复/重新开方
6. 重新收费、发药、执行

**没有做“一键自动换药”**：收费后的处方不能直接改，必须走退药/退费，避免绕过财务和库存。

## 边界

- 已执行药品不能自动回补库存，需药房退药确认
- 药物反应不自动上报不良反应监测系统
- 没有过敏/相互作用自动重新计算，只记录本次反应
- 没有“换药原因”结构化字典，目前是文本
