# 医嘱状态与 DC 规则

## 一、现实医院中的做法（审查结论）

DC 的正确含义是“停止医嘱/停嘱”，不是“删除医嘱”，也不等于退费。常见流程：

1. 医生开立医嘱；
2. 护士接收/校对；
3. 执行科室执行；
4. 执行后按频次继续。

对应的操作边界：

- **护士接收前**：可删除/作废；
- **长期医嘱护士接收后**：用“停止医嘱（DC）”停止后续执行，已经执行的次数保留；
- **临时医嘱护士接收后**：可作废；已执行不能作废；
- **已经执行/已发药/已完成**：不能 DC 掉历史，只能走退药、退费、退检等流程；
- 医嘱作废或停止后不能继续执行；
- 手术、转科、出院时长期医嘱通常自动停止；
- 门诊处方更常用“作废、退药、退费”，DC 更多用于住院长期医嘱。

因此，“必须先完整结算才能 DC”并不准确：**是否已执行**才是关键；结算不是 DC 的前置条件，结算后也不允许把已完成项目 DC 成未发生，只能退费/退药。

## 二、本系统映射

本系统现在是门诊场景，采用：

### cancelled（作废/撤回）

- 尚未发送/执行；
- 医生端隐藏；
- 接收科室不显示；
- 未收费费用同步取消。

### dc（停止/DC）

- 已发送但尚未执行；
- 医生端保留；
- 接收科室保留；
- 显示“已停止（DC）”；
- 不允许采样、检查、发药、执行；
- 已收费用的退款走收费处退费。

### 已执行/已发药/已完成

- 不允许 DC；
- 走退药、退费、退检、退治流程；
- 保留执行记录。

当前覆盖检验、检查、处方、治疗。住院长期医嘱的“停嘱/重整医嘱/预停”属于后续住院模块扩展，不在门诊客户端伪造。

## 三、接口

- 检验：`POST /lab/requests/{id}/cancel`
- 检查：`POST /pacs/requests/{id}/cancel`
- 处方：`POST /encounters/{encounter_id}/prescriptions/{prescription_id}/stop`
- 治疗：`POST /treatments/{id}/cancel`
