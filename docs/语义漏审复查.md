# 全系统语义级漏审复查

日期：2026-11-24
范围：62 个后端模块、40 个 UI 文件、25 个顶层工作站/96 个页签

## 一、复查方法

不是只跑接口，而是对每个模块同时检查六个维度：

1. **模型**：该结构化的字段是否只是自由文本；
2. **顺序**：临床/业务动作的先后是否符合实际流程；
3. **状态**：状态值是否有明确含义、合法迁移和并发保护；
4. **权限**：谁能做、谁不能做；
5. **审计**：关键动作是否留操作人/时间/原因；
6. **测试**：测试是否只断言 200，而没有断言临床/业务语义。

## 二、本轮确认并修复的漏审

### 1. 诊断只有主/次，没有阶段和确定性

- 新增 `diagnosis_stage`：outpatient / admission / discharge；
- 新增 `diagnosis_phase`：initial / provisional / corrected / final；
- 新增 `diagnosis_certainty`：pending / suspected / confirmed；
- 迁移 `0115`；
- 诊断编辑器新增阶段、分期、确定性下拉，表格增加对应列；
- “暂记待查”写入：阶段门诊、分期暂定、确定性待查；
- 诊断位置移到病史/查体/辅助检查之后、处理意见之前。

### 2. 分诊队列没有按病情分级排序

原实现按 `id` 排序，先到先叫，4 级非急症可能排在 1 级濒危前面。已改为：

```text
triage_level ASC → created_at ASC → id ASC
```

同时把叫号/过号改成条件 UPDATE，避免并发重复叫号。

### 3. 检验工作列表忽略加急

原实现按 `id DESC`，加急标本没有优先。已改为：

```text
urgent 优先 → requested_at ASC → id ASC
```

### 4. 挂号没有取消/释放号源

新增 `POST /registrations/{id}/cancel`：

- 仅 `registered` 可取消；
- 已接诊不能取消；
- 释放 `doctor_schedules.booked`；
- 重复取消返回 400。

### 5. 护理高警示药品未优先

原护士执行单按 id 倒序，高警示药品可能排在普通输液之后。已改为：

```text
high_alert DESC → status ASC → id ASC
```

### 6. 代煎处方头状态断链

代煎只改 `TcmPrescription.status`，统一处方头停在 `dispensing`。已改为包装完成时把 header 置 `dispensed`，并加测试断言。

### 7. 快速挂号绕过查重

快速挂号直接调用 `create_patient`，没有走完整建档的重复档案确认。已改为先调用 `check_patient_duplicates`，有候选档案时弹出“使用已有档案/取消”，与完整建档一致；EMPI 合并仍待补。
