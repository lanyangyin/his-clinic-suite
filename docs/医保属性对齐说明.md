# 医保属性对齐说明

目标：现在不接医保，但把本地目录和入库明细的医保属性先存全，未来接医保接口时直接映射。

## 四类对象

### 药品

已有字段：

- 药品名称、规格、单位、剂型、厂家、批准文号
- 医保编码 `insurance_code`
- 医保类别 `insurance_category`（甲/乙/丙/自费/未对码）
- 匹配状态 `insurance_match_status`

### 医用耗材

`material_items` 新增：

- `insurance_name`
- `insurance_category`（甲/乙/丙/自费/未对码）
- `insurance_match_status`（matched/ambiguous/unmatched）
- 原有 `insurance_code`、厂家、注册证号、规格

### 医疗服务项目

`charge_items` 新增：

- `insurance_code`
- `insurance_name`
- `insurance_category`
- `insurance_match_status`
- `unit`（次/项/床位等）
- `reimbursement_note`

管理台“收费项目”页面可直接填写。

### 诊断/手术操作

字典 `dict_entries` 新增 `category`：

- `diagnosis_icd10`：诊断
- 后续可增加 `operation_icd9`：手术操作
- 字典编码本身作为医保编码/标准编码

## 入库快照

`inbound_items` 新增并保存：

- `insurance_code`
- `insurance_name`
- `insurance_category`
- `insurance_match_status`
- `dosage_form`
- `approval_no`

入库时：

1. 优先使用入库行填写的医保属性
2. 未填写时从药品/耗材目录带出
3. 保存为入库明细快照，后续目录改名/改码不影响历史批次

桌面端库房入库页新增“医保属性（快照）：编码 / 名称 / 甲乙丙类别”一行，待提交明细表增加“医保编码/医保类别”两列。

## 类别取值

统一为：

- `甲`
- `乙`
- `丙`
- `自费`
- `未对码`

匹配状态：

- `matched`
- `ambiguous`
- `unmatched`

## 边界

- 没有连接国家医保目录接口，属性需人工维护或按官方文件导入。
- 没有自动校验编码是否真的存在。
- 收费项目目前只保存属性，不参与医保结算。
- 历史入库单的新字段为空，需要时补录。
- 没有目录版本号/生效日期，后续接官方目录时再加。
