# HIS 门诊部系统 · 部署手册

目标场景：一台服务器电脑 + 若干工作站（≤10 台），局域网内使用。

## 一、服务端部署

### 方式 A：源码方式（开发/试用机，已装 Python）

```powershell
uv sync
uv run python scripts/init_db.py      # 新库：建表并标记版本；存量库：增量升级
uv run python scripts/seed_demo.py    # 可选：演示账号与基础数据
```

双击 `start.bat` 启动。启动时读取程序目录下 `config.ini`：

```ini
[server]
host = 0.0.0.0      ; 局域网访问用 0.0.0.0；仅本机用 127.0.0.1
port = 8000
secret_key = 请改成随机字符串
[database]
url =               ; 留空 = 程序目录下 his.db
```

### 方式 B：打包版（推荐，服务器无需 Python）

1. 在打包机执行 `scripts\build_server.bat`，生成 `dist\his-server.zip`；
2. 解压到服务器任意目录（如 `D:\HIS-Server`，**不要放 C:\Program Files**）；
3. 编辑 `config.ini`（端口、密钥、监听地址）；
4. 双击 `his-server.exe` 启动：
   - 首次启动自动建库 + 建表 + 标记版本；
   - **自动创建初始管理员 `admin / admin123`**（请立即在管理台新建正式账号）；
5. 防火墙放行端口：
   ```powershell
   netsh advfirewall firewall add rule name="HIS" dir=in action=allow protocol=TCP localport=8000
   ```
6. 局域网访问：`http://<服务器IP>:8000/admin`（管理台）、`/docs`（API 文档）、`/download/client`（客户端下载）。

> 若首次启动中途被强制关闭导致建库不完整：停止服务 → 删除 `his.db` → 重新启动即可（数据为空，属于首次部署场景）。

### 开机自启（二选一，均需管理员权限）

| 方式 | 操作 | 说明 |
|---|---|---|
| 任务计划（简单） | 右键 `install_autostart.bat` → 以管理员身份运行 | 开机自动启动 `his-server.exe`；卸载运行 `uninstall_autostart.bat` |
| Windows 服务（推荐） | 下载 [NSSM](https://nssm.cc) 的 `nssm.exe` 放到 `tools\` 下，右键 `install_service.bat` 以管理员身份运行 | 服务名 `HISServer`，日志在 `logs\server.log`；卸载运行 `uninstall_service.bat` |

## 二、客户端部署（绿色 zip）

1. 管理台点「客户端下载」，或取 `dist\his-client.zip`；
2. 解压到工作站任意目录（如 `D:\HIS-Client`）；
3. 编辑同目录 `config.ini`：
   ```ini
   [server]
   url = http://192.168.1.10:8000
   [client]
   timeout = 10
   ```
4. 双击 `his-client.exe`，用账号登录。

客户端**整目录自包含**（Python、Qt 依赖都在目录内），不安装任何东西、不写注册表。

## 三、账号与权限

| 账号 | 可进入的工作站 |
|---|---|
| admin | 管理台 + 全部工作站 |
| cashier | 收费员工作站：建档/挂号/收费/退费/打印 |
| doctor | 医生工作站：叫号接诊/结构化病历（质控/签名）/开方（含用法）/检验检查开单/治疗开单 |
| pharmacist | 药房工作站：入库/发药/退药/库存查询 |
| nurse | 护士工作站：分诊叫号/治疗执行 |

全新部署自动创建 `admin/admin123`；首次登录后请立即修改密码、新建实际员工账号。

## 四、目录结构（程序自包含）

```
HIS-Server/                 ← 服务端程序目录（整个目录可拷走）
├─ his-server.exe           ← 双击启动（内置 Python/依赖）
├─ config.ini               ← 服务端配置（端口/密钥/数据库）
├─ his.db                   ← 数据库（含 his.db-wal / his.db-shm）
├─ backups/                 ← 备份（backup.bat 生成）
├─ logs/                    ← 服务日志（NSSM 方式）
├─ backup.bat               ← 一键备份
├─ install_service.bat      ← 安装为 Windows 服务（需 tools\nssm.exe）
├─ install_autostart.bat    ← 开机任务计划启动
└─ uninstall_*.bat          ← 卸载脚本

HIS-Client/                 ← 客户端目录（整个目录可拷走）
├─ his-client.exe
├─ config.ini               ← 服务器地址
└─ 其余为运行时依赖
```

**运行期文件写入范围**：服务端只写程序目录（`his.db`、`backups/`、`logs/`）；不写 `%APPDATA%`、注册表或系统目录。客户端只读同目录 `config.ini`，运行期不产生文件。

## 五、备份与恢复

- 备份：双击 `backup.bat`，生成 `backups\his_日期_时间.db`；建议每天下班前执行，并复制到U盘/网盘。
- 恢复：停止服务 → 备份文件改名为 `his.db` 覆盖 → 重启。

## 六、换设备迁移

### 服务端（打包版，推荐）

1. 停止服务；
2. 拷贝整个 `HIS-Server` 目录到新机器（必须含 `his.db`、`backups/`、`config.ini`）；
3. 双击 `his-server.exe` 即可（无需安装 Python）。

### 服务端（源码方式）

1. 停止服务；
2. 拷贝整个项目目录（含 `his.db`、`backups/`、`config.ini`）；
3. 新机器安装 Python 3.12 + uv，执行 `uv sync`、`uv run python scripts/init_db.py`；
4. 双击 `start.bat`，管理台验证数据完整。

### 客户端

1. 拷贝整个 `HIS-Client` 目录到新电脑；
2. 改 `config.ini` 的服务器地址；
3. 双击 `his-client.exe` 运行。

### 注意事项

- 迁移前务必先备份 `his.db`；迁移后确认 `config.ini` 的端口/密钥一致；
- 服务端和客户端目录都不要放在 `C:\Program Files` 等受保护目录（读写受限），建议 `D:\HIS`；
- 多台工作站共用同一服务端时，客户端只改 `config.ini`，不要各自建库。

## 七、注意事项

1. **SQLite 适用规模**：单机或 ≤10 台工作站、并发收费不高的场景。若工作站更多或频繁并发写入，应迁移 PostgreSQL（改造方案已评估，可按需实施）。
2. 服务端与客户端均只在局域网使用；不要直接暴露到公网。
3. 医院数据敏感：`admin/admin123` 为初始弱口令，上线前必须更换；管理台密钥通过 `config.ini` 或环境变量 `HIS_SECRET_KEY` 注入。
4. 客户端打印通过浏览器打开打印页（处方 A5 / 小票 58mm），需在工作站配置默认打印机。

## 八、Linux（Ubuntu/Debian）部署

服务端与桌面客户端依赖已分离（PySide6 在 `client` 可选依赖中），**Linux 服务器无需任何图形库**。

### 源码方式（已验证）

```bash
sudo apt update && sudo apt install -y python3.12 python3.12-venv
# 安装 uv（如未装）: curl -LsSf https://astral.sh/uv/install.sh | sh
uv sync                 # 只装服务端依赖
./start.sh              # 初始化数据库并启动（等价 start.bat）
```

- 备份：`./backup.sh`
- 端口/密钥：编辑 `config.ini`；也可用环境变量 `HIS_HOST` / `HIS_PORT` / `HIS_SECRET_KEY` / `HIS_DATABASE_URL` 覆盖

**实测记录**：Ubuntu 24.04 + Python 3.12.3 上，全量 456 个测试通过（84.9s），全新库初始化后服务启动，`/version` 200、管理台登录页 200。

### systemd 服务（开机自启）

```bash
sudo ./scripts/install_service.sh     # 安装并启动 his.service
systemctl status his                  # 查看状态
journalctl -u his -f                  # 查看日志
sudo ./scripts/uninstall_service.sh   # 卸载
```

### 打包 Linux 服务端

PyInstaller **不能跨平台**（Windows 打的 exe 不能在 Linux 用）。在 Linux 机器上执行：

```bash
uv sync
./scripts/build_server.sh
# 产物：dist/his-server-linux.zip
```

### 说明

- 数据库、备份、配置都在程序目录（与 Windows 版一致），迁移=拷贝整个目录；
- 客户端仍是 Windows 程序（PySide6），Linux 机器可用浏览器访问管理台/API 文档，或另行在 Linux 上从源码运行客户端（`uv sync --extra client && uv run python -m his_client`）。

## 九、手机 Termux（仅演示/应急）

**结论：技术上可行，但不建议作为生产环境。**

### 推荐：proot-distro 装 Ubuntu（兼容性最好）

```bash
pkg install proot-distro
proot-distro install ubuntu
proot-distro login ubuntu
apt update && apt install -y python3.12 python3.12-venv
# 然后按“Linux 源码方式”部署：uv sync && ./start.sh
```

### 原生 Termux（不推荐）

Termux 是 Android 环境，PyPI 的 manylinux 轮子不可用，需要源码编译：`pkg install python rust clang binutils`，再 `pip install`（pydantic-core 需 Rust 编译，耗时长且可能失败）。服务端依赖已拆分去掉 PySide6，但仍有编译门槛。

### 注意事项

- 手机休眠/省电策略会杀进程：需 `termux-wake-lock`，并关闭电池优化；
- 仅适合本机或同一 WiFi 下小范围演示；手机发热、断网、电量都会影响可用性；
- 数据在手机应用私有目录，务必定期 `./backup.sh` 并导出；
- 多个工作站长期使用请用电脑/服务器（Windows 或 Ubuntu），不要依赖手机。


## 十、常见问题

| 问题 | 排查 |
|---|---|
| 客户端提示「无法连接服务器」 | 服务器是否启动、`config.ini` 的 url 是否为服务器 IP、防火墙是否放行 8000 |
| 管理台打不开 | 访问 `/admin`；未登录会跳转登录页 |
| 服务端启动报端口占用 | 改 `config.ini` 的 `port` 或关闭占用程序 |
| 首次启动建库失败 | 停止服务 → 删除 `his.db` → 重新启动（首次部署场景） |
| 数据在哪 | 服务端程序目录下 `his.db`（备份即复制该文件） |
| 换电脑后数据没了 | 确认拷贝了 `his.db`，而不是只拷了程序代码 |
| 客户端界面字体异常 | 工作站为 Windows 10/11 即可正常显示中文；如异常检查系统字体 |
