# 多诊断与门诊病历格式

## 参考

- 《病历书写基本规范》门诊病历：初诊/复诊均应包含诊断、治疗意见、医师签名
  https://www.tjzyefy.com/system/2024/11/20/030153415.shtml
- 门诊病历书写内容：主诉、现病史、既往史、阳性/必要阴性体征、辅助检查、诊断、处理意见
- 同类 HIS 门诊医生站普遍采用“主诊断 + 其他诊断”，按重要性排序

## 诊断规则

- 一次就诊可写多条诊断
- **第一行为主诊断**
- 后续为其他诊断，按重要性从上到下
- 最多 20 条
- 同一诊断不能重复
- 保存后主诊断同步写入 `encounters.diagnosis/diagnosis_code`，兼容旧处方、打印、统计
- 已收费关闭的就诊不能修改

## 数据表

```text
encounter_diagnoses
- id
- encounter_id
- diagnosis_code
- diagnosis
- diagnosis_type: primary / secondary
- sort_no
- note
- created_at
```

旧数据自动回填为一条主诊断。

## 病历页排版

```text
就诊 ID / 载入病历 / 诊断摘要
┌ 诊断（第一行为主诊断，按重要性排序）────────────┐
│ 顺序  类型      编码    诊断          备注      │
│ 1     主诊断    I10     高血压                  │
│ 2     其他诊断          2型糖尿病      合并症   │
│ [添加/更新] [删除选中] [上移] [下移]             │
│ [保存全部诊断]                                  │
└──────────────────────────────────────────────┘
主诉 / 现病史
既往史 / 个人史
婚育史 / 家族史
体格检查 / 辅助检查
处理意见
[保存/更新] [签名锁定] [质控评分]
```

门诊工作台还保留“主诊断”快捷输入，旁边“多诊断”打开完整列表；开始接诊前录入的多条诊断会在接诊成功后自动保存。

## 接口

```text
GET /encounters/{id}/diagnoses
PUT /encounters/{id}/diagnoses
```

保存示例：

```json
[
  {"diagnosis_code": "I10", "diagnosis": "高血压", "note": "主要"},
  {"diagnosis": "2型糖尿病", "note": "合并症"}
]
```

返回按顺序的诊断，第一条 `diagnosis_type=primary`。

## 打印

门诊病历打印按顺序输出：

```text
诊断：
1.【主诊断】I10 高血压
2.【其他诊断】2型糖尿病（合并症）
```

处方笺仍显示主诊断，保持处方简洁。
