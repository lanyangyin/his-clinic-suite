# 管理员身份与快速建档

## 管理员现在有哪些身份

`admin` 仍然拥有全部工作站入口：

```text
人事
收费
门诊
患者360
药房
库房
护士
检验
病案
院长审批
中药/煎药
治疗室
药事审核
库房审核
治疗项目审批
```

其中检验、药房、库房、院长的业务权限通过 `admin` 超级管理员权限放行，不需要为每个部门再造一个账号。

## 管理员医生档案

为了让管理员在门诊现场挂号时能作为医生使用，服务端启动时执行：

```text
ensure_admin_doctor(db)
```

行为：

1. 找到 `admin` 用户
2. 如果 `users.doctor_id` 已存在，跳过
3. 没有则查找名为“管理员”的医生档案
4. 没有则创建：
   - 姓名：管理员
   - 科室：第一个启用科室；没有则创建“综合门诊”
5. 回写 `admin.doctor_id`

新字段：

```text
users.doctor_id
```

迁移：

```text
0092_user_doctor_link
```

之后：

```text
/auth/me 返回 doctor_id
医生站快速建档默认选中该医生
```

## 快速建档：是否立即挂号

医生端和收费端都改为单选：

```text
( ) 仅建档，暂不挂号
(•) 建档后立即挂号
```

按钮名称从“快速建档并挂号”改成“快速建档”。

### 仅建档

- 只创建患者档案
- 不创建挂号
- 不需要选择医生
- 提示“已按仅建档处理，未挂号”

### 建档后立即挂号

- 创建患者档案
- 使用当前选择医生挂号
- 管理员默认选“管理员”对应的医生
- 挂号成功后显示挂号 ID

### 为什么这样改

原来“快速建档并挂号”把两个动作绑死：

- 只想建档时被迫挂号
- 建档后不挂号没有入口
- 医生没选好时无法先保存患者

单选把决定权交给用户，同时保留高频的“建档后立即挂号”默认值。

## 管理员医生档案的边界

这是一个**真实存在的医生档案**，会出现在医生列表中，也会参与挂号。

如果诊所不希望管理员出现在排班/医生列表，可以后续增加：

```text
doctors.is_admin_profile = true
```

默认从普通排班列表过滤，但快速挂号仍可使用。

当前版本没有加这个字段，先保证管理员能作为医生完成门诊流程。
