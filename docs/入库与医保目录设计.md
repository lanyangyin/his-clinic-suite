# 入库与医保目录改造设计

## 一、现状问题

1. 药房 `stock-in` 只接收药品，没有"单据"概念：无供应商、随货同行单、发票号、验收记录，不符合药品经营/使用单位的收货验收规范。
2. 器械、耗材、办公用品（打印机/打印纸）分散在 materials 模块，无法与药品走同一套收货流程。
3. 药品主数据缺少医保贯标码、批准文号、生产厂家、剂型，无法与医保目录对码。
4. 没有本地医保目录库，处方/收费无法校验"目录内/目录外、甲乙类、限定支付范围"。

## 二、目标模型

### 1. 入库单（新模块 `receiving`，独立于发药）

- `inbound_orders`：单号、类型（drug 药品 / device 器械 / consumable 耗材 / office 办公用品 / other）、供应商、来源（采购/退货/捐赠/调拨）、状态 `received → checked → stocked`（或 `cancelled`）、随货同行单号、发票号、收货人/验收人/时间。
- `inbound_items`：药品或物资、名称/规格/单位快照、批号、效期、数量、单价、金额、医保贯标码、器械注册证号、生产厂家、储存条件（常温/阴凉/冷藏）、不合格数量与原因、库房/货位。
- 库存落点：
  - 药品 → 药房批次库存 `drug_stocks`（同药同批合并）；
  - 物资/器械/办公 → `material_stocks`（按库房合并）。
- 只入"合格数量"（到货数量 − 不合格数量）。

### 2. 医保药品目录（新模块 `insurance_catalog`）

- `insurance_drugs`：国家医保药品代码（贯标码，唯一）、通用名、剂型、规格、生产厂家、单位、甲乙丙类、限定支付范围、批准文号、有效期起止、来源版本。
- `insurance_catalog_versions`：版本号、来源（manual/auto）、文件名、行数、SHA-256 校验和、操作人、导入时间。

## 三、医保对药品入库的要求（设计依据）

| 要求 | 落地方式 |
|---|---|
| 医保贯标（国家医保代码/通用名/剂型/规格/厂家） | 药品主数据增加 `insurance_code / approval_no / manufacturer / dosage_form`；入库明细带 `insurance_code` |
| 甲乙类、限定支付范围 | 目录字段 `category / reimbursement_note`，供处方与收费校验 |
| 进销存数据上传（批号、效期、数量、金额、供应商、发票） | 入库单 + 明细字段完整留痕，后续对接上传接口 |
| 目录外药品自费 | 目录未匹配 → 标记丙类/目录外，收费按自费处理 |
| 追溯码 | 后续在入库/发药扫码环节扩展（本期预留批号/效期字段） |

## 四、医疗规范要点

- **药品**：必须登记批号、有效期、储存条件，按批入库、近效期先出；验收记录不合格数量与原因。
- **医疗器械**：必须登记注册证号/备案号；无菌器械需灭菌批号（后续扩展字段）。
- **办公用品**：简化验收，只记数量/单价。
- 供应商、随货同行单号、发票号、收货人/验收人全部留痕，便于追溯与检查。

## 五、接口

```
POST /inbound/orders                 创建入库单（收货）
GET  /inbound/orders?status=&order_type=
GET  /inbound/orders/{id}
POST /inbound/orders/{id}/check      验收（登记不合格）
POST /inbound/orders/{id}/stock      入库（写库存）
POST /inbound/orders/{id}/cancel     取消（未入库）

POST /insurance/catalog/import       上传 CSV/XLSX（admin）
GET  /insurance/catalog/search?q=&category=
GET  /insurance/catalog/versions
POST /insurance/catalog/sync         从 URL 拉取更新（admin）
GET  /insurance/catalog/{code}
```

兼容性：药房旧 `POST /pharmacy/stock-in` 保留（内部/旧客户端仍可用）；新业务统一走入库单。

## 六、医保目录更新策略

1. **手动**：管理台上传表格（下一步加页面），或直接调导入接口。
2. **自动**：`scripts/sync_insurance_catalog.py` 从 `config.ini [insurance_catalog] url` 拉取，
   配合 Windows 任务计划 / Linux cron 定时执行；内容 SHA-256 未变化时自动跳过（`unchanged`）。
3. **版本留痕**：每次成功导入生成版本记录（来源/文件/行数/校验和/操作人）。
4. **失败保护**：拉取或解析失败不写版本、不破坏现有目录数据。

## 八、两级库存与库房出库（v0.6.0）

### 库存归属

| 层级 | 库存表 | 说明 |
|---|---|---|
| 总库（药库/物资总库） | `warehouse_stocks`（药品批次）、`material_stocks`（warehouse=总库） | 入库单只入总库 |
| 药房 | `drug_stocks`（药品批次） | 药房发药扣这里 |
| 科室 | `material_stocks`（warehouse=科室名） | 出库目标为科室时落这里 |

### 流程

```
入库单（收货→验收）→ 总库
药房/科室「领用出库」申请 → 库房「审核」→ 库房「出库」
  → 扣总库，增药房批次库存 / 科室物资库存
药房发药 → 扣药房库存
```

- 出库单状态：`submitted 已申请 → approved 已审核 → issued 已出库`（或 `cancelled`）。
- 出库校验：总库批次库存不足时拒绝；并发用条件更新（`quantity >= 出库量`）。
- 药品出库未填效期时，自动取总库批次的效期写入药房库存。
- 管理台「库房」页负责审核/出库；客户端药房只提交申请和查看状态。

### 后续可加

- 库存流水台账（每笔入/出/调拨记账，医保进销存上传）
- 库房管理员独立角色（当前用 pharmacist 兼任）
- 报损/退货出库、盘点差异自动生成调整单
- 冷链温度记录、效期预警

## 九、库存流水台账

表 `stock_movements`：物品（药品/物资）、批次、效期、库房、方向（in/out）、数量、单价、金额、**结存 balance_after**、单据类型/ID（purchase/inbound/outbound/dispense/dispense_return/transfer/adjust/usage）、操作人、时间。

记录点：
- 入库单入库（总库）、采购、调拨（总库→药房双向）、盘点差异（盘盈/盘亏）
- 库房出库（总库 out + 药房/科室 in）
- 药房发药（药房 out）、退药（药房 in）、住院摆药/退药
- 物资入库/高值耗材使用

接口：`GET /stock/ledger?kind=&warehouse=&direction=&ref_type=&start_date=&end_date=`；管理台「库存流水」页可按类型/库房/方向/单据类型筛选，供医保进销存上传与追溯。

## 十、部分出库 / 退库 / 报损 / 盘点调整单

- **部分出库**：出库明细新增 `issued_quantity`；可多次出库，状态 `partially_issued`，全部出完转 `issued`。
  接口 `POST /warehouse/outbound-orders/{id}/issue`，body 可选 `{"items":[{"item_id":1,"quantity":4}]}`；不传 body 表示出全部剩余。
- **退库**：药房发起 `outbound_type=return`（目标=药房/科室），库房审核/出库后从药房批次退回总库，双向记流水（ref_type=return）。
- **报损**：库房创建 `outbound_type=scrap`，出库只扣总库、不增目标库存，流水 ref_type=scrap。
- **盘点差异调整单**：盘点 `check` 产生差异时自动生成 `stock_adjustments`（盘盈/盘亏、账面/实盘/差异、关联盘点记录），流水 ref_type=adjust 指向调整单。
- **权限**：药房可创建领用/退库；库房可创建报损/调拨；审核/出库仅库房。
- 管理台出库详情支持按明细填写数量部分出库；库房页展示调整单列表。

## 十一、效期预警与近效期先出（FEFO）

- **效期预警**：`GET /warehouse/expiry-alerts?days=90` 返回 `expired`（已过期）与 `near_expiry`（近效期）批次，覆盖总库与药房，仅统计数量>0；含剩余天数。
- **管理台**：「效期预警」页可调天数，分开展示过期/近效期。
- **客户端**：库房/药房工作站均有「效期预警」页签。
- **近效期先出（跨批次）**：领用出库单的药品行可**不填批号**，出库时自动按总库批次效期从早到晚分配（过期批次排除），按各批次分别扣减、增加药房库存并记流水；支持部分出库时再次自动分配。
- 指定批号的出库/退库/报损仍按单批次处理；药房发药本身已按近效期先出扣减。

## 十二、医保目录对码与处方/收费校验

- **药品字段**：`insurance_code`（贯标码）、`insurance_category`（甲/乙/丙）、`insurance_match_status`（matched/ambiguous/unmatched）。
- **对码规则**：贯标码精确匹配优先；否则按 **名称+剂型+规格** 唯一匹配（忽略空格/全角差异）；多个候选标记歧义，不自动改代码。
- **接口**：`POST /insurance/catalog/match?only_unmatched=true` 批量对码；`GET /insurance/catalog/matches` 状态列表；`GET /insurance/catalog/resolve/{drug_id}` 单药校验结果。
- **管理台**：医保目录页新增「药品对码」区（自动对码按钮 + 状态/类别/命中目录）。
- **处方校验**：甲类报销 100%；乙类按药品维护比例；丙类/代码未匹配目录 → 0（自费，允许开方并提示）；未对码药品保留原手工比例（兼容历史）。
- **收费校验**：处方明细保存 `insurance_category` 与比例快照，收费按快照计算医保支付/自费金额（`insurance_amount` / `self_pay_amount`）。
- **客户端**：医生药品目录显示医保类别（甲/乙/丙/未对码/歧义）；收费对话框展示医保与自费金额。

## 十三、药品追溯码扫码

- 表 `drug_trace_codes`：追溯码全局唯一、药品/批号、当前库房（总库/药房）、状态（in_stock/used/returned/void）、单据、患者/就诊、操作人、时间。
- 流程：**入库扫码**登记到总库（校验批次库存与重复码）→ **出库扫码**移到药房 → **发药扫码**核销并关联就诊/患者 → **退药扫码**回到药房在库。
- 接口：`POST /trace/scan/inbound|outbound|dispense|return`、`GET /trace/codes`、`/trace/codes/summary`、`/trace/codes/{code}`。
- 权限：入库/出库扫码归库房；发药/退药扫码归药房；管理台可查询全部。
- 客户端「追溯码」页支持扫码枪回车连续录入、模式切换、批量提交与按码查询；管理台「追溯码」页可筛选/汇总。

## 十四、医保进销存上传

- 表 `insurance_inventory_uploads`：上传单号、期间、条数、金额、状态（submitted/success/failed）、报文、回执、操作人、时间。
- 明细来源：`stock_movements`（仅药品），字段含医保代码/名称/规格/剂型/单位/批次/效期/库房/业务类型/方向/数量/单价/金额/发生时间/单据/结存；未对码药品计入 `unmatched_count`。
- 接口：`POST /insurance/inventory/preview`、`POST /insurance/inventory/upload`（Mock 医保接收，返回回执号）、`GET /insurance/inventory/uploads[/{id}]`；管理台「医保进销存」页可预览、上传、查看历史与报文。
- 定时：`scripts/upload_insurance_inventory.py --days 1`（Windows 任务计划/Linux cron），真实环境把 Mock 提交替换为医保平台接口。

## 十五、医保接口配置（真实上传适配）

- 管理台新增「医保接口」页：平台地址、上传路径、机构编码/名称、AppID、AppSecret、签名方式（NONE/HMAC-SHA256/SM2）、SM2 私钥/公钥、超时、备注、启用开关。
- **默认全部留空**：未启用或平台地址/机构编码为空时，进销存上传自动走 Mock（`channel=mock`），可先体验完整流程，实际部署时再填写。
- 密钥/私钥/公钥输入框留空表示**保持原值**，页面只显示掩码，不回显明文。
- 启用后走真实 HTTPS：`POST {base_url}{upload_path}`，请求体 `{org_code, app_id, timestamp, nonce, data}`，请求头含 `X-Org-Code / X-App-Id / X-Timestamp / X-Nonce / X-Sign`；`X-Sign` 按 HMAC-SHA256（机构码+时间戳+随机串+报文）或 SM2 生成。
- 回执处理：`code` 为 `0/200/SUCCESS` 视为成功，其余为失败；网络异常/超时/非 JSON/HTTP 4xx-5xx 均记为失败并保留回执摘要；`insurance_inventory_uploads.channel` 区分 mock/http。
- 测试策略：默认空白配置验证 Mock 回退；测试中通过管理台表单填入平台地址/机构码/AppID/Secret，并 monkeypatch `requests.post` 模拟医保平台，验证 URL、请求体、HMAC 签名、成功回执、平台拒绝、连接失败分支。
- 实际对接需按当地医保接口规范调整字段名、报文格式、签名算法与回执校验。

## 十六、客户端页签拆分与入库目录下拉

- **药房/库房独立页签**：客户端不再合并为一个"药房/库房工作站"；管理员登录后分别显示「药房工作站」「库房工作站」两个独立页签，药房账号只看到药房、库房账号只看到库房。
- **入库药品下拉默认医保目录**：入库单的"药品来源"默认选「医保目录（默认）」，下拉列出本地已导入/同步的医保目录药品（名称+规格+类别），可切换「本店药品」。
- 选中目录药品后，客户端调用 `POST /insurance/catalog/{national_code}/ensure-drug` 自动落地/复用本地药品（同医保代码幂等），再用该 `drug_id` 创建入库明细；目录为空时提示并自动回退本店药品。
- **关于"公开 API"**：官网/公众号可以**免登录查询**（国家医保局微信公众号「微服务→国家医保药品目录查询」；医用耗材见国家医保局医保医用耗材分类与代码数据库 code.nhsa.gov.cn），但这是面向人的查询页面/目录文件，**没有面向开发者的公开 API 文档与稳定接口**；页面多为动态请求、可能反爬且受使用条款约束，生产系统不宜依赖抓取。本系统通过管理台上传 CSV/XLSX 或配置官方文件 URL 同步获取目录，未使用非官方抓取；管理台已附官方查询入口链接。医用耗材/器械目录同样按官方文件/授权接口发布，后续可用同一导入机制扩展。

## 十七、医用耗材目录与物资下拉

- 新增表 `insurance_materials`：医保耗材编码（唯一）、名称、类别、规格、型号、厂家、单位、类型（耗材/器械/办公）、注册证号、备注。
- 导入：管理台「耗材目录」页上传 CSV/XLSX（表头支持「医用耗材编码/耗材名称/规格/型号/生产厂家/单位/类别/耗材类型/注册证号/备注」），按编码 upsert；也支持 `POST /insurance/materials/sync` 从官方文件 URL 同步。
- 落地：`POST /insurance/materials/{code}/ensure-item` 按编码复用/创建本地 `MaterialItem`，完整医保编码保存到 `material_items.insurance_code`（本地 code 超长时自动生成 HC 前缀短码）。
- 客户端入库物资行新增「物资来源」下拉，默认 **医保耗材目录（默认）**，选中后自动落地本地物资；目录为空回退「本店物资」。
- 官方查询入口：医保医用耗材分类与代码数据库 https://code.nhsa.gov.cn（公开查询，无公开 API）。

## 十八、界面汉化

- 接口和数据库内部仍使用英文状态值（便于对接与兼容），**只在前端显示层翻译成中文**。
- 管理台新增统一标签过滤器：入库状态（已收货/已验收/已入库/已取消）、出库状态（已申请/已审核/部分出库/已出库/已取消）、单据类型（采购入库/入库单/出库单/发药/退药/退库/报损/盘点调整）、角色（管理员/医生/护士/收费员/药师/库房管理员/检验技师/影像技师）、审计方法/状态码、追溯码状态、进销存上传状态与通道、签名方式等。
- 客户端新增 `his_client/labels.py`：挂号/就诊/收费/退费/发药/退药/叫号/治疗/追溯码/出入库状态全部中文显示，状态栏角色也显示中文。
- 覆盖页面：仪表盘、审计日志、用户管理、入库单、库房/出库单、库存流水、追溯码、医保目录/耗材目录、医保进销存/接口配置，以及客户端收费/医生/药房/库房/护士工作站。
