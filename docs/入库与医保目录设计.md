# 入库与医保目录改造设计

## 一、现状问题

1. 药房 `stock-in` 只接收药品，没有"单据"概念：无供应商、随货同行单、发票号、验收记录，不符合药品经营/使用单位的收货验收规范。
2. 器械、耗材、办公用品（打印机/打印纸）分散在 materials 模块，无法与药品走同一套收货流程。
3. 药品主数据缺少医保贯标码、批准文号、生产厂家、剂型，无法与医保目录对码。
4. 没有本地医保目录库，处方/收费无法校验"目录内/目录外、甲乙类、限定支付范围"。

## 二、目标模型

### 1. 入库单（新模块 `receiving`，独立于发药）

- `inbound_orders`：单号、类型（drug 药品 / device 器械 / consumable 耗材 / office 办公用品 / other）、供应商、来源（采购/退货/捐赠/调拨）、状态 `received → checked → stocked`（或 `cancelled`）、随货同行单号、发票号、收货人/验收人/时间。
- `inbound_items`：药品或物资、名称/规格/单位快照、批号、效期、数量、单价、金额、医保贯标码、器械注册证号、生产厂家、储存条件（常温/阴凉/冷藏）、不合格数量与原因、库房/货位。
- 库存落点：
  - 药品 → 药房批次库存 `drug_stocks`（同药同批合并）；
  - 物资/器械/办公 → `material_stocks`（按库房合并）。
- 只入"合格数量"（到货数量 − 不合格数量）。

### 2. 医保药品目录（新模块 `insurance_catalog`）

- `insurance_drugs`：国家医保药品代码（贯标码，唯一）、通用名、剂型、规格、生产厂家、单位、甲乙丙类、限定支付范围、批准文号、有效期起止、来源版本。
- `insurance_catalog_versions`：版本号、来源（manual/auto）、文件名、行数、SHA-256 校验和、操作人、导入时间。

## 三、医保对药品入库的要求（设计依据）

| 要求 | 落地方式 |
|---|---|
| 医保贯标（国家医保代码/通用名/剂型/规格/厂家） | 药品主数据增加 `insurance_code / approval_no / manufacturer / dosage_form`；入库明细带 `insurance_code` |
| 甲乙类、限定支付范围 | 目录字段 `category / reimbursement_note`，供处方与收费校验 |
| 进销存数据上传（批号、效期、数量、金额、供应商、发票） | 入库单 + 明细字段完整留痕，后续对接上传接口 |
| 目录外药品自费 | 目录未匹配 → 标记丙类/目录外，收费按自费处理 |
| 追溯码 | 后续在入库/发药扫码环节扩展（本期预留批号/效期字段） |

## 四、医疗规范要点

- **药品**：必须登记批号、有效期、储存条件，按批入库、近效期先出；验收记录不合格数量与原因。
- **医疗器械**：必须登记注册证号/备案号；无菌器械需灭菌批号（后续扩展字段）。
- **办公用品**：简化验收，只记数量/单价。
- 供应商、随货同行单号、发票号、收货人/验收人全部留痕，便于追溯与检查。

## 五、接口

```
POST /inbound/orders                 创建入库单（收货）
GET  /inbound/orders?status=&order_type=
GET  /inbound/orders/{id}
POST /inbound/orders/{id}/check      验收（登记不合格）
POST /inbound/orders/{id}/stock      入库（写库存）
POST /inbound/orders/{id}/cancel     取消（未入库）

POST /insurance/catalog/import       上传 CSV/XLSX（admin）
GET  /insurance/catalog/search?q=&category=
GET  /insurance/catalog/versions
POST /insurance/catalog/sync         从 URL 拉取更新（admin）
GET  /insurance/catalog/{code}
```

兼容性：药房旧 `POST /pharmacy/stock-in` 保留（内部/旧客户端仍可用）；新业务统一走入库单。

## 六、医保目录更新策略

1. **手动**：管理台上传表格（下一步加页面），或直接调导入接口。
2. **自动**：`scripts/sync_insurance_catalog.py` 从 `config.ini [insurance_catalog] url` 拉取，
   配合 Windows 任务计划 / Linux cron 定时执行；内容 SHA-256 未变化时自动跳过（`unchanged`）。
3. **版本留痕**：每次成功导入生成版本记录（来源/文件/行数/校验和/操作人）。
4. **失败保护**：拉取或解析失败不写版本、不破坏现有目录数据。
