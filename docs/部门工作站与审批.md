# 部门工作站与审批流

## 已新增的工作站

不新增重复角色，直接扩展现有部门账号：

| 部门账号 | 新增工作站 | 职责 |
|---|---|---|
| `pharmacist` 药房/药师 | 药事审核工作站 | 审核医生提交的新药品建议 |
| `warehouse` 库房 | 库房审核工作站 | 对药事通过的新药品做最终审核并建立药品档案 |
| `director` 院长 | 治疗项目审批 | 审批医生提交的新治疗项目并建立治疗收费项目 |

管理员仍可进入全部工作站。

## 医生提交建议

医生端增加：

```text
开方 → 建议新增药品
治疗 → 建议新增治疗项目
```

填写：

```text
名称
规格
单位
建议价格
理由/适应症
```

提交后只生成 `catalog_proposals` 记录，**不会直接写药品目录或收费项目**。

## 药品审批链

```text
医生提交
→ pending_pharmacy
→ 药事审核通过
→ pending_warehouse
→ 库房审核通过
→ 建立 Drug 主数据
→ approved
```

任一步驳回：

```text
→ rejected
```

医生只能看自己的建议状态，不能编辑目录。

## 治疗项目审批链

```text
医生提交
→ pending_director
→ 院长审批通过
→ 建立 ChargeItem，category=treatment
→ approved
```

驳回：

```text
→ rejected
```

## 权限

| 动作 | 角色 |
|---|---|
| 提交建议 | doctor |
| 查看自己的建议 | doctor |
| 药事审核 | pharmacist |
| 库房最终审核 | warehouse |
| 治疗项目审批 | director |
| 全部 | admin |

## 前端入口

- 医生：开方页、治疗页的“建议新增…”按钮
- 药房：`药事审核工作站`
- 库房：`库房审核工作站`
- 院长：`治疗项目审批`

## 还没做的

### 采购执行

现有采购申请仍由管理台完成：

```text
库房发起采购
→ 院长批准
→ 管理台下单/收货
```

客户端目前只新增了“新药品建议”的审核，不直接生成采购单。

下一步可以把采购申请做成库房工作站的“采购执行”页签：

- 查看已批准采购申请
- 下单
- 分批收货
- 批号/效期录入
- 入库

### 医务科

治疗项目目前由院长直接审批。  
如果诊所规模扩大，可以增加：

```text
medical_affairs（医务科）
```

审批链改为：

```text
医生 → 医务科 → 院长
```

当前版本不虚构这个角色。
